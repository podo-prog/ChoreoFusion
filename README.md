# ChoreoFusion 구간 검출: 사용한 데이터·모델·처리 과정

> 이 문서는 이 대화방의 결정과 결과, 그리고 로컬 ChoreoFusion 프로젝트 파일에서 확인한 구현 정보를 정리합니다. GitHub 저장소는 개인 계정 `podo-prog` 아래 비공개로 만들었습니다. 현재 이 저장소에는 이 문서만 올리며 원본 BVH/FBX와 모델 가중치는 포함하지 않습니다.

## 1. 목표

BVH 또는 FBX 모션 파일에서 춤 동작 구간의 시작·끝을 자동으로 찾고, 사용자의 기존 annotation JSON 형식으로 구간을 출력합니다. 각 구간의 `label`은 비워 둡니다.

이 작업의 목표는 동작 이름, 의미, 수행 품질을 분류하는 것이 아닙니다. 학습 목표는 사람이 표시한 시간 구간의 경계를 재현하는 것입니다.

## 2. 입력 데이터와 라벨

- 사람 손으로 구간을 나눈 29곡을 사용했습니다.
- 곡별 BVH와 FBX 모션 파일, 구간 범위가 담긴 JSON을 사용했습니다.
- JSON의 `전체 동작 설명` 레이어에서 시작·끝 시각만 학습 정답으로 사용했습니다.
- 자연어 설명, 태그, S/H/R/E 표기는 무시했습니다.
- WAV와 PKL은 이 모델 학습과 추론에 사용하지 않았습니다.
- 겹친 구간을 바로잡은 BackAllBlack JSON을 기존 파일 대신 사용했습니다.
- BVH/FBX가 한 곡의 짝으로 다른 데이터 분할에 들어가지 않도록 곡 단위로 나눴습니다.

## 3. 후보 비교와 모델 실험 순서

처음에는 CNN, LSTM, GRU와 TCN을 비교했고, 연속 프레임의 경계를 찾는 목적에 맞춰 TCN 계열을 중심으로 실험했습니다. 대화 및 프로젝트 폴더에 정리된 버전은 다음 다섯 가지입니다.

1. Dilated TCN, 30Hz
2. Dilated TCN, 60Hz
3. Dilated TCN, 120Hz
4. ActionFormer, 120Hz
5. MS-TCN++ 스타일 경계 모델 + ST-GCN 경계 검증기, 120Hz

최종 선택 모델은 5번입니다. ActionFormer는 별도 버전으로 보관했습니다. ST-GCN은 동작 의미나 품질을 분류하지 않고, 경계 신뢰도를 보조하는 역할로 사용했습니다.

## 4. 최종 모델 처리 흐름

1. BVH/FBX 모션을 공통 120Hz 시간축으로 변환합니다.
2. 관절 위치와 움직임에서 모션 특징을 계산합니다.
3. MS-TCN++ 스타일 다단계 temporal convolution 모델이 프레임별 경계 신뢰도를 예측합니다.
4. ST-GCN이 51개 관절의 연결 구조와 시간 변화를 이용해 경계 점수를 보조 검증합니다.
5. BVH와 FBX의 예측 점수를 결합하고, 점수 임계값과 최소 경계 간격으로 경계 후보를 디코딩합니다.
6. 경계 사이를 빈 라벨 구간으로 만들고 원본 JSON annotation 형식으로 저장합니다.

로컬 ChoreoFusion 구현에서 확인되는 최종 모델 구성은 MS-TCN++ 스타일 4단계, 48채널, 단계당 7개 temporal convolution 층입니다. ST-GCN은 51개 관절 그래프를 입력으로 사용합니다. 입력 특징 차원은 학습 보고서 기준 414입니다.

## 5. 학습과 디코더 설정

29곡을 곡 단위로 학습 18곡, 검증 5곡, 보류 6곡으로 분리했습니다. 우선 검증 5곡에서 경계 목표 폭, 점수 임계값, 최소 간격 조합을 비교하고, 선택한 설정으로 29곡 전체를 다시 학습했습니다.

최종 설정:

- 샘플링: 120Hz
- 경계 목표 폭: 0.075초
- 경계 점수 임계값: 0.30
- 검출 경계 사이 최소 간격: 0.375초
- 일괄 시간 오프셋: 0초
- 평가 시 허용오차: 가장 가까운 120Hz 프레임이 같은 경계만 일치로 계산

0.375초는 너무 촘촘한 검출을 줄이는 후처리 간격입니다. 사용자가 실제 라벨에서 이보다 짧은 구간도 표시한 적이 있어, 짧은 동작 경계를 억제할 위험이 있습니다.

## 6. 오늘 생성한 결과

- Crazy 테스트용 JSON: 27개 빈 라벨 구간
- ChillKill 테스트용 JSON: 31개 빈 라벨 구간
- ChillKill 수동 정답 JSON: 사용자가 기존 31구간 예측을 수정해 27구간으로 만든 파일

ChillKill 수정에서 기존 경계 20개는 유지하고, 6개를 옮겼으며, 4개를 삭제했습니다. 이 JSON은 예측 결과를 수정해 만든 자료이므로 독립적인 테스트 정답으로 간주하면 안 됩니다. 수정본은 아직 모델 가중치에 재학습 반영하지 않았습니다.

## 7. 검증 결과와 한계

정확 프레임 기준 내부 점수는 검증 5곡 macro F1 3.1%, 보류 6곡 macro F1 2.9%였습니다. 이는 현재 경계 예측기가 엄격한 프레임 단위 기준에 크게 못 미친다는 뜻입니다. 이 수치는 Crazy나 ChillKill의 테스트 점수가 아닙니다.

ChillKill의 수정 JSON에서 변경된 부분은 초반의 일부 경계가 예측보다 늦어졌고, 12.9~14.7초 부근의 여러 조각이 더 긴 구간으로 합쳐졌습니다. 따라서 정확 프레임 일반화 성능과 경계 과분할 문제가 남아 있습니다.

## 8. 구현 환경과 다른 기능의 구분

로컬 프로젝트의 의존성 파일에는 Python 3.12용 실행 환경 안내와 함께 NumPy, PyTorch, scikit-learn, joblib, `pufbx`가 기재돼 있습니다. 경계 모델은 NumPy/PyTorch를 사용하고, FBX 입력은 `pufbx`로 읽습니다. scikit-learn/joblib은 기존의 수동 분할 구간 군집 기능에 쓰이며, 이번 자동 경계 검출의 최종 모델은 아닙니다.

프로젝트에 있던 PCA/K-means 군집 기능은 이미 잘라 놓은 BVH 구간을 모으는 별도 기능입니다. 여기서 다룬 자동 구간 검출 모델과 혼동하지 않습니다.

## 10. 다음에 반영할 점

ChillKill 수정본은 보정 학습 예제로 추가할 수 있지만, 학습에 넣는 순간 독립 테스트 자료가 아닙니다. 수정본을 포함한 새 모델 버전을 따로 만들고, 다음 검증은 예측 파일에서 수정하지 않은 새 곡의 정답으로 진행해야 합니다. 엄격한 프레임 점수가 낮으므로, 후처리 값만 바꾸기보다 시작·끝 경계의 직접 예측과 구간 구조를 함께 학습하는 방식도 검토 대상입니다.
